# Malware Analysis Report

## Summary
The analyzed code demonstrates clear malicious intent focused on **Information Theft (SMS Exfiltration)** and **Social Engineering**. The application extracts sensitive SMS data stored in `SharedPreferences` and exfiltrates it by sending it as SMS messages to remote numbers controlled by the attacker. Additionally, the app uses dynamic resource loading to display deceptive notifications and UI elements that redirect users to external URLs or trigger phone calls, likely for fraudulent purposes.

**Identified Malicious Behaviors:**
*   **SMS Data Exfiltration:** `com.googleapi.cover.Utils.start` - Sends stolen SMS data to remote phone numbers via `SmsManager`.
*   **SMS Data Retrieval:** `com.googleapi.cover.MessageHandler.onReceive` - Retrieves sensitive SMS content from `SharedPreferences`.
*   **Deceptive Notifications:** `com.googleapi.cover.Notifier.showNotification` - Displays notifications with dynamically loaded URLs and text to redirect users.
*   **Social Engineering UI:** `com.googleapi.cover.ShowURL.onCreate` - Displays a "grant access" screen that prompts users to visit URLs or call a "support" number.
*   **Device/Network Metadata Collection:** `com.googleapi.cover.TextUtils` - Extracts MCC, MNC, and SIM operator information.

---

## Malicious Call Chain
The following call chain illustrates how the application performs the SMS exfiltration:

`com.googleapi.cover.MessageHandler.onReceive` 
$\rightarrow$ `com.googleapi.cover.Utils.start` 
$\rightarrow$ `android.telephony.SmsManager.sendTextMessage`

**Explanation:**
1.  **`com.googleapi.cover.MessageHandler.onReceive`**: This component acts as the trigger. It retrieves sensitive SMS data (`smsData`) from the device's `SharedPreferences` and prepares a list of destination phone numbers and ports. It then calls the `Utils.start` method to process this data.
2.  **`com.googleapi.cover.Utils.start`**: This method receives the stolen data and the list of target numbers. It iterates through the list and uses the system's `SmsManager` to send the stolen data as a text message to each number in the list.
3.  **`android.telephony.SmsManager.sendTextMessage`**: The final system call that executes the actual transmission of the stolen information via the cellular network.

## Detailed Analysis

**com.googleapi.cover.Utils.start**
The method `start` in `com.googleapi.cover.Utils` is the core exfiltration engine. It utilizes `SmsManager.getDefault().sendTextMessage` to iterate through a list of phone numbers (`actScheme.list.get(i).first`) and sends the `data` (which contains the stolen SMS content) to those numbers. The message body is constructed by concatenating a value from the scheme with the stolen data.

**com.googleapi.cover.MessageHandler.onReceive**
In `com.googleapi.cover.MessageHandler.onReceive`, the application intercepts an intent and accesses `SharedPreferences` to retrieve a string identified by `Actor.KEY_MSG_DATA_TEXT`. This string contains the sensitive SMS information. Once retrieved, it initializes a list of destination parameters and passes the stolen data to `Utils.start` to begin the exfiltration process.

**com.googleapi.cover.Notifier.showNotification**
In `com.googleapi.cover.Notifier.showNotification`, the application dynamically constructs a notification. It uses `TextUtils.read` to pull a URL, a title, and a body from a raw resource file (`R.raw.act_schemes`). The notification is configured with a `PendingIntent` that opens a web browser to the retrieved URL, allowing the attacker to control the content and destination of the notification remotely.

**com.googleapi.cover.ShowURL.onCreate**
In `com.googleapi.cover.ShowURL.onCreate`, the application presents a user interface designed for social engineering. It displays a URL and a "support number." The "support number" is linked to an `Intent` with the action `android.intent.action.CALL`, which forces the device to dial the number when the user interacts with the text, a common tactic in technical support scams.

**com.googleapi.cover.TextUtils**
The `com.googleapi.cover.TextUtils` class provides several utility methods for gathering reconnaissance data. Specifically, `getMCC`, `getMNC`, and `getOperatorString` are used to extract the Mobile Country Code and Mobile Network Code from the SIM card. This information helps the attacker identify the user's location and service provider. Additionally, `read` is used to parse the `R.raw.act_schemes` file, which serves as a remote configuration file for the app's malicious activities.
